# 寻宝值怎样影响 Chronicon 掉宝

本结论来自当前安装文件的内置帮助、原生程序反汇编，以及当前游戏进程实测。不是从其他游戏的寻宝公式推断。

## 核心结论

寻宝值是 **Magic Find**。内置帮助 `locale/EN/help/9.txt` 明确说明，它提高获得更稀有装备及本职业装备的机会，原生上限为 **999%**。`playerStatSetCaps` 中也确实存在对该属性取 `min(寻宝值,999)` 的处理。

它不是装备等级，不是「每增加 1% 就增加 1 个掉落」，也不是一个稀有度选择开关。单靠提高寻宝值，通常只能改变概率，不能排除其他品质。要选择品质，修改器需要另外覆盖随机装备生成器的品质参数。

## 当前生成器的概率关系

`itemGenerate` 接收有效寻宝参数 F，并在生成器内部计算：

```text
M = 1 + F / 100
```

因此，当某次生成收到 F=82 时，倍率是 1.82；F=999 时倍率是 10.99。这里的 F 是生成器收到的参数。不同怪物、掉落来源及其他生成条件可能影响传入参数，不能将这张表直接当成每次击杀的最终掉率。

当前原生分支中，默认随机范围为 0–12000，按优先级进行品质判定；各分支可能重新抽取随机数。观察到的判定阈值如下：

| 品质分支 | 默认阈值 | 额外条件 |
| --- | --- | --- |
| 真传奇 | 5 × M | 等级、难度及来源资格；可用物品池 |
| 传奇 | 60 × M | 难度／来源资格；可用物品池 |
| 独特 | 200 × M | 可用物品池与职业匹配 |
| 稀有 | 1000 × M | 前面品质分支未成功 |
| 附魔 | 5500 × M | 前面品质分支未成功 |
| 普通 | 剩余情况 | 前面品质分支未成功 |

这是**生成器分支的阈值**，不是最终掉落分布。随机数为整数、比较是否通过、较高品质是否已经命中、资格门槛、物品池重试和掉落来源都会影响结果。强制奖励和某些特殊掉落也不遵循这条默认随机链。

当阈值足够大，某个符合资格的分支可以覆盖整个随机数范围，但这仍不会创建物品池中不存在的装备或自动提高装备等级。

寻宝值还参与降低低品质装备选到其他职业的机会。当前生成器中有 `clamp(9 - 最大玩家寻宝值 / 20, 0, 9)` 的中间量，再用于职业随机判定；这不是「掉率 9%」或简单的最终职业概率。

## 品质选择怎样实现

当前生成器已经支持指定品质参数：

| 参数 | 含义 |
| --- | --- |
| -4 | 按原概率随机 |
| 0 | 普通 |
| 1 | 附魔 |
| 2 | 稀有 |
| 3 | 独特 |
| 4 | 传奇／套装 |
| 4.2 | 真传奇分支 |

修改器只把 **-4 随机参数**替换成选择值，保留其他明确指定的品质。它在游戏选取物品及生成词条之前传入品质，避免只改颜色而保留不匹配的装备内容。明确指定品质的特殊奖励和制作配方保持原行为。

寻宝值控制在原生 999% 上限处理之后写入玩家的数值字段，因此可设超上限值；它不改等级、装备词条、难度或怪物战斗属性。

## 版本与验证依据

- 游戏文件：`D:\GAME\STEAM\steamapps\common\Chronicon\Chronicon.exe`
- SHA-256：`ab163214859c2fb4dad2a433ea937ca9a8ee8d2b99d2a856b74310723d24800c`
- 属性补丁位置：主模块 RVA `0x18C3A8E`，原指令长度 18 字节。
- 随机品质参数补丁位置：主模块 RVA `0xE9390C`，原指令长度 17 字节。
- 安装前同时检查文件哈希及原指令；使用运行时模块基址，支持地址随机化。
- 更新指令时短暂暂停进程；正常退出恢复并回读原指令。跳板保留至游戏退出，避免释放仍被游戏线程引用的内存。
- 属性实测：82 → 125 → 999 → 82；原指令恢复已确认。
- 品质实测：传奇参数覆盖 8 次随机生成，用户确认新掉落为传奇／套装。
- 六个品质的参数转换、固定品质保留与关闭覆盖，均通过原生 x64 测试；真传奇等其他品质尚未逐项验证真实掉落。

不能据此声称所有掉落来源都已测试，或神话／制作专属物品可以通过寻宝值直接获取。
